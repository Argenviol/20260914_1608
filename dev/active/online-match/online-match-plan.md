# 온라인 실시간 대전 — 계획

방 코드를 주고받아 각자 집에서 두는 1:1 온라인 대전.

## 결정된 것

- **보안 수준**: "내 증강은 내 컴퓨터가 책임" (사용자 선택)
  비밀 증강은 주인 클라이언트만 알고 있다가, 발동하는 순간 공개 + 결과만 상대에게 보낸다.
  F12 로는 안 보인다. 패킷을 뜯는 수준은 막지 않는다.
- **비용**: 0원. 이미 연결된 Render 워크스페이스(`My Workspace`)에 무료 웹 서비스로 배포.
  무료 등급은 15분 놀면 잠들고 첫 접속에 ~50초 걸린다 → "서버 깨우는 중" 안내로 덮는다.
  나중에 이 지연이 거슬리면 Cloudflare Workers + Durable Object 로 옮긴다 (프로토콜 그대로).

## 아키텍처: 상태 전송 (state transfer)

### 왜 lockstep(입력만 전송)이 아닌가

게임 흐름에 무작위가 하나도 없어서(`Math.random` 은 AI·효과음·연출에만 있음) lockstep 이 성립하기는 한다.
하지만 lockstep 은 양쪽이 같은 계산을 돌린다는 뜻이고, 그러려면 상대 클라이언트도 내 비밀 증강 id 를 알아야 한다.
**비밀 증강을 지키기로 한 이상 lockstep 은 못 쓴다.**

그래서 **판을 바꾼 쪽이 결과 상태를 보낸다.** 받는 쪽은 계산하지 않고 그대로 채택한다.

부수 효과로 어긋남(desync) 자체가 생길 수 없고, 재접속도 마지막 상태만 다시 주면 끝난다.

### 턴 경계 — 이미 코드에 있다

`game.js` 의 `doMove()` 는 이렇게 끝난다.

```js
await fire('onOppMoved', opp(side), { move });   // 상대 소유 훅. 프롬프트 없음(B1b 하나뿐, 자동)
await beginTurn(G.turn);                          // ← 여기서부터 상대가 답해야 하는 프롬프트가 나온다
```

`beginTurn` 안에서 도는 것(`onSched`·`onTurnStart`·`onCheck`)은 전부 **차례가 시작되는 쪽**의 것이고,
`B3c` 부활 선택처럼 사람에게 묻는 게 들어 있다. 반대로 `onOppMoved` 는 구현이 `B1b` 하나뿐이고 자동이다.

→ **둔 사람 클라이언트는 `beginTurn` 직전까지 돌리고 상태를 보낸다. `beginTurn` 은 받는 쪽이 자기 화면에서 돌린다.**

```
[백 클라이언트]                          [흑 클라이언트]
doMove
 ├ 이동·처치·증강 훅
 ├ 드래프트 (백이 고름)
 ├ 시계 차감, ply++, 만료/포영 복귀
 ├ onOppMoved (자동)
 └ 상태 전송 ───────────────────────────▶ 상태 채택 → 렌더
                                          beginTurn('b')
                                           ├ onSched (흑이 고름)
                                           ├ onCheck
                                           └ 판이 바뀌었으면 상태 되돌려보냄 ◀── (핑퐁 안 생김: 아래 참고)
                                          흑이 둔다 → doMove …
```

핑퐁 방지: 받는 쪽은 `G.turn === 내 색` 일 때만 `beginTurn` 을 돈다.
되돌려 보낸 상태에서도 `G.turn` 은 여전히 흑이므로, 백은 `beginTurn` 을 돌리지 않는다.

## 비밀 증강 가리기

각 클라이언트는 **자기편의 아직 공개되지 않은 비밀 증강 id** 를 가면으로 바꿔 보낸다.

- 가면 id: `?w1`, `?b2` …
- 가면은 `AUG_BY_ID` 에 `{id, piece, tier, secret:true, tag:'비밀', text:'발동 전까지 비공개', terms:[]}` 로 등록한다.
  - 기존 UI 의 숨김 분기(`augCard` 가 `piece`·`tier` 만 보여줌)가 그대로 돌아간다. 지금도 딱 그만큼만 공개한다.
  - `B11c`(상대의 특정 기물 강화 제거)가 `AUG_BY_ID[id].piece` 를 읽는데, 가면에 `piece` 가 있어서 정상 동작한다.
    → 상대 비밀 증강도 기물 종류 기준으로는 제대로 지워진다.
  - `augCountFor` 도 `piece` 기준이라 그대로 맞는다.
- 자기 상태를 되받을 때는 **자기 map 으로 원복**한다 (`maskMap['?w1'] = 'B1c'`). map 은 그 클라이언트 밖으로 안 나간다.
- 발동하면 이미 `api.reveal(id)` 가 돌고 있다. 그때부터 진짜 id 를 실어 보낸다.

## 상태 직렬화 — 무엇을 보내나

전부 보내되, 커지는 두 가지는 뺀다.

| 항목 | 처리 |
|---|---|
| `bd` | 64칸 `[type, color, id, moved]` 또는 `null` |
| `turn ply ep kills tierIdx eff phased grave flags revealed hist lastBySide clock result moveNo` | 그대로 |
| `augs` | 자기편 비밀은 가면으로 |
| `log` | **새로 늘어난 줄만.** 받는 쪽이 이어붙인다 |
| `snaps` | **안 보낸다.** 받는 쪽이 채택 직후 자기가 `pushSnapshot` 한다 (판을 이미 갖고 있으므로 똑같이 만들어진다) |

한 수당 3~5KB 예상.

## 시계

각 클라이언트가 자기 시계를 돌린다. 둔 사람이 자기 남은 시간을 차감해서 상태에 실어 보낸다.
시간 초과 선언은 **기다리는 쪽**이 한다 (수혜자이고 확실히 접속해 있으므로). 네트워크 여유로 2초 유예.

## 파일

| 파일 | 상태 | 할 일 |
|---|---|---|
| `server/relay.py` | 신규 | 정적 파일 + WebSocket 중계, 방 코드, 마지막 상태 보관 (파이썬 표준 라이브러리만) |
| `game/src/net.js` | 신규 | 접속·방·프로토콜·가면·직렬화 |
| `game/src/game.js` | 수정 | `mode:'online'`, `beginTurn` 경계, 상태 채택 |
| `game/src/ui.js` | 수정 | 메인에 온라인 카드, 대기 화면, `canControl`, "상대가 고르는 중" |
| `game/index.html` | 수정 | `net.js` 추가, 온라인 카드 마크업 |

## 단계

1. 서버 (중계 + 정적) — 로컬에서 두 탭으로 검증
2. `net.js` 직렬화/가면 — 순수 함수라 단위 검증 가능
3. `game.js` 턴 경계
4. `ui.js` 방 만들기/참가/대기/차례 표시
5. 로컬 2탭 통합 검증 (증강·비밀·시계·재접속)
6. Render 배포 (사용자 확인 후)
