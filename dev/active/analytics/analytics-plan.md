# 대국 통계 수집 (수퍼베이스)

## 왜
증강별 선택률·승률, 평균 대국 시간, 어떤 기물을 많이 쓰는지를 보려면
**여러 사람이 실제로 둔 판**이 모여야 한다. 지금 게임은 아무 데도 데이터를 보내지 않는다.

## 한 줄 요약
브라우저가 대국이 끝날 때 요약을 **렌더의 릴레이 서버**로 보내고,
릴레이가 수퍼베이스에 적는다. 수퍼베이스 키는 **서버 환경변수에만** 둔다.

## 왜 브라우저에서 수퍼베이스로 바로 안 보내나
정적 사이트라 브라우저에 넣는 키는 누구나 볼 수 있다.
릴레이를 한 번 거치면 키가 안 나가고, 서버에서 **아는 칸만 골라 담고**(화이트리스트)
IP별 횟수 제한도 걸 수 있다. 게임 화면 자체가 이미 릴레이에서 나가므로 같은 출처다.

## 데이터 단위 — '한 사람이 겪은 한 판'
한 판에 한 줄이 아니라 **사람마다 한 줄**(`plays`)로 남긴다.

- AI·2인 대전: 두 진영 모두 한 줄씩 (AI 는 `is_ai = true`)
- 온라인: 각자 자기 것만 한 줄 — 상대의 비밀 증강은 내 화면에 가면으로만 오니
  상대 줄을 내가 대신 쓸 수 없다. 같은 방은 `room` 으로 나중에 짝지을 수 있다.

이렇게 하면 두 클라이언트가 대국 id 를 맞출 필요가 없다. 조율이 없으니 어긋날 일도 없다.

## 표 두 개
- `plays` — 사람마다 한 판. 승패·사유·수·시간·처치·보유 증강·기물별 이동/처치
- `aug_picks` — 증강을 고른 순간마다 한 줄. 제시된 3개·잠긴 것·고른 것·고민 시간·시간초과 여부

`aug_picks.play_id → plays.id` 로 이어서 **증강별 승률**을 낸다.

## 단계
1. `game/src/stats.js` — 대국 중 모았다가 끝날 때 한 번 보낸다
2. `game.js` / `ui.js` 에 수집 지점 연결 (이동·처치·드래프트·종료)
3. `server/relay.py` 에 `POST /api/stat` — 화이트리스트 + 크기·횟수 제한 후 수퍼베이스로
4. `docs/분석_수퍼베이스_설정.md` — 표 만드는 SQL 과 렌더 환경변수 설정 순서
5. 메인 화면에 끄는 스위치 (기본 켬, 익명)

## 안 하는 것
- 개인정보. 기기마다 만든 임의의 익명 id 말고는 아무것도 안 보낸다.
- 기보 전체. 판마다 요약만 보낸다.
