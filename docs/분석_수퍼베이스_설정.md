# 대국 통계 — 수퍼베이스 설정

게임은 판이 끝날 때 요약을 **렌더의 서버**로 보내고, 서버가 **수퍼베이스**에 적는다.

```
브라우저 ──POST /api/stat──▶ 렌더 (relay.py) ──REST──▶ 수퍼베이스
                                    └ 키는 여기에만 있다
```

브라우저에서 수퍼베이스로 바로 안 보내는 이유: 정적 사이트라 **브라우저에 넣은 키는 누구나 볼 수 있다.**
서버를 한 번 거치면 키가 안 나가고, 아는 칸만 골라 담고(화이트리스트), IP별 횟수 제한도 걸린다.

---

## 1단계 — 수퍼베이스 프로젝트 만들기

1. <https://supabase.com> 에서 **Start your project** → 깃허브 계정으로 로그인
2. **New project**
   - Name: `muje-chess` (아무거나)
   - Database Password: 아무거나 (이 프로젝트에서는 안 쓴다. 혹시 모르니 적어 두기)
   - Region: **Northeast Asia (Seoul)** — 서울이 없으면 Tokyo
   - Plan: **Free**
3. 만들어지는 데 1~2분 걸린다.

> 무료 요금제: 데이터베이스 500MB, 한 달 5GB 전송. 이 게임의 한 판은 1KB 정도라
> 무료로 **수십만 판**을 담을 수 있다. 다만 **7일 동안 아무도 안 쓰면 잠시 멈춘다**(대시보드에서 깨우면 된다).

## 2단계 — 표 두 개 만들기

왼쪽 메뉴 **SQL Editor** → **New query** → 아래를 통째로 붙여넣고 **Run**.

```sql
-- 한 사람이 겪은 한 판
create table plays (
  id            uuid primary key,
  created_at    timestamptz not null default now(),
  client_id     text,          -- 기기마다 만든 익명 id. 사람을 알아내는 값이 아니다.
  app_version   text,
  mode          text,          -- 'ai' | 'pvp' | 'online'
  difficulty    text,          -- ai 일 때만
  tc            text,          -- 제한시간 표기
  room          text,          -- 온라인 방 코드 (같은 판끼리 짝짓기용)
  side          text,          -- 'w' | 'b'
  is_ai         boolean,
  outcome       text,          -- 'win' | 'lose' | 'draw'
  reason        text,          -- 체크메이트 · 시간 초과 · 항복 ...
  moves         int,
  plies         int,
  duration_ms   bigint,
  kills         int,
  opp_kills     int,
  tier_reached  int,           -- 0~4 (1·3·6·11 처치 중 몇 번째까지)
  augs          text[],        -- 끝났을 때 가지고 있던 증강
  piece_moves   jsonb,         -- {"p":12,"n":4}
  piece_kills   jsonb          -- {"q":3}
);

-- 증강을 고른 순간마다 한 줄
create table aug_picks (
  id         uuid primary key,
  created_at timestamptz not null default now(),
  play_id    uuid not null references plays(id) on delete cascade,
  ply        int,
  tier       int,        -- 1 · 3 · 6 · 11
  piece      text,       -- 무엇으로 처치해서 열렸나
  offered    text[],     -- 제시된 3개
  blocked    text[],     -- 그 중 ✕ 로 잠겨 있던 것
  chosen     text,
  think_ms   int,        -- 고민한 시간 (판 보기로 멈춘 시간은 빠진다)
  auto       boolean,    -- 30초를 넘겨 무작위로 골랐나
  is_ai      boolean
);

create index on plays (created_at);
create index on plays (mode, outcome);
create index on aug_picks (chosen);
create index on aug_picks (play_id);

-- 아무나 읽고 쓰지 못하게 잠근다.
-- 서버는 service_role 키로 들어와서 이 잠금을 통과한다.
alter table plays     enable row level security;
alter table aug_picks enable row level security;
```

**성공하면** "Success. No rows returned" 이 뜬다.

## 3단계 — 주소와 키 복사

왼쪽 아래 **⚙ Project Settings** →

- **Data API** 메뉴 → **Project URL**
  `https://xxxxxxxxxxxx.supabase.co` ← 이게 `SUPABASE_URL`
- **API Keys** 메뉴 → **service_role** 옆 **Reveal** → 복사
  `eyJhbGciOi...` (아주 길다) ← 이게 `SUPABASE_SERVICE_KEY`

> ⚠️ **service_role 키는 절대 깃허브나 채팅에 올리지 않는다.** 이 키는 위에서 건 잠금을 통과한다.
> `anon` 키(바로 위에 있는 것)와 헷갈리지 말 것 — anon 은 잠금에 막혀 아무것도 못 적는다.

## 4단계 — 렌더에 환경변수 넣기

1. <https://dashboard.render.com> → 서비스 **muje-chess** 클릭
2. 왼쪽 **Environment** → **Environment Variables** 의 **+ Add Environment Variable**
3. 두 개를 넣는다.

   | Key | Value |
   |---|---|
   | `SUPABASE_URL` | `https://xxxxxxxxxxxx.supabase.co` (끝에 `/` 없이) |
   | `SUPABASE_SERVICE_KEY` | `eyJhbGciOi...` (아까 복사한 긴 것) |

4. **Save, rebuild, and deploy** — 저장하면 알아서 다시 뜬다. 1~2분.

넣지 않아도 게임은 그대로 돌아간다. 통계만 조용히 버려질 뿐이다.

---

## 5단계 — 들어오는지 확인

1. 배포된 주소에서 **한 판을 끝까지** 둔다 (항복도 된다. **중단은 안 된다** — 승패가 아니라서 안 보낸다).
2. 수퍼베이스 → **Table Editor** → `plays` 에 줄이 생겼는지 본다.

안 보이면 렌더의 **Logs** 를 본다. `[stat] 전송 실패:` 로 시작하는 줄이 있으면 그게 이유다.

| 로그에 보이는 것 | 뜻 |
|---|---|
| `HTTP Error 401` | 키가 틀렸다. anon 키를 넣었거나 복사가 잘렸다 |
| `HTTP Error 404` | 주소가 틀렸거나 표 이름이 다르다 |
| `HTTP Error 400` | 표의 칸이 위 SQL 과 다르다 |
| 아무것도 없음 | 환경변수가 비어 있다 (그러면 서버는 그냥 버린다) |

## 뽑을 수 있는 것

SQL Editor 에 붙여 쓰면 된다.

**증강별 선택률** — 나왔을 때 몇 번이나 골랐나

```sql
select a.aug,
       count(*)                                   as 제시,
       count(*) filter (where a.aug = a.chosen)   as 선택,
       round(100.0 * count(*) filter (where a.aug = a.chosen) / count(*), 1) as 선택률
from (select unnest(offered) as aug, chosen from aug_picks where not is_ai) a
group by a.aug
having count(*) >= 5
order by 선택률 desc;
```

**증강별 승률**

```sql
select p.aug,
       count(*) as 판수,
       round(100.0 * count(*) filter (where pl.outcome = 'win') / count(*), 1) as 승률
from (select id, unnest(augs) as aug from plays where not is_ai) p
join plays pl on pl.id = p.id
group by p.aug
having count(*) >= 5
order by 승률 desc;
```

**평균 대국 시간 · 수**

```sql
select mode,
       count(*)                                  as 판수,
       round(avg(duration_ms) / 60000.0, 1)      as 평균분,
       round(avg(moves), 1)                      as 평균수
from plays where not is_ai group by mode;
```

**어떤 기물로 많이 잡았나**

```sql
select k.key as 기물, sum(k.value::int) as 처치
from plays, jsonb_each(piece_kills) k
where not is_ai
group by k.key order by 처치 desc;
```

**티어 도달률** — 1·3·6·11 처치까지 몇 %가 갔나

```sql
select tier_reached, count(*),
       round(100.0 * count(*) / sum(count(*)) over (), 1) as 비율
from plays where not is_ai group by tier_reached order by tier_reached;
```

**✕ 로 잠겨 못 고른 비율** — 선택지가 실제로 몇 개였나

```sql
select cardinality(blocked) as 잠긴수, count(*),
       round(100.0 * count(*) / sum(count(*)) over (), 1) as 비율
from aug_picks where not is_ai group by 1 order by 1;
```

**승부가 어떻게 났나**

```sql
select reason, count(*) from plays where not is_ai group by reason order by 2 desc;
```

**고민 시간이 긴 증강** — 어렵거나 애매한 선택지

```sql
select chosen, count(*), round(avg(think_ms) / 1000.0, 1) as 평균초,
       count(*) filter (where auto) as 시간초과
from aug_picks where not is_ai and chosen is not null
group by chosen having count(*) >= 5 order by 평균초 desc;
```

## 무엇을 보내고 무엇을 안 보내나

**보낸다** — 대국 모드·승패·사유·수·걸린 시간·처치 수·고른 증강·기물별 이동/처치,
그리고 기기마다 처음 한 번 만든 **임의의 id**(같은 사람이 여러 판 둔 걸 묶기 위한 것).

**안 보낸다** — 이름·이메일·IP·기보 전체·대화 내용. 아무것도.

플레이하는 사람은 메인 화면 아래 **📊 통계** 버튼으로 끌 수 있다. 끄면 그 기기에서는 아무것도 안 나간다.
